**Brush batching implementation: measured results**

25 October 2026. Implemented fallback triangle-ID generation, partial index uploads and cold index-only reloads for batch visibility, and CPU-only preparation for strokes finalized immediately into a batch. Partial vertex uploads and SRP batching remain unimplemented. This report is local and untracked.

**Measured outcome.** The full ID pass reduced managed allocation churn and improved CPU time moderately. The subset pass removed repeated whole-mesh array copies, producing a much larger improvement. Nonzero-offset subset IDs are also corrected. These measurements explicitly invoke the fallback on a Windows Editor; they are not application frame-rate, desktop-player, or mobile-device results.

**Memory and correctness.** Warmed operations within the cache cap allocated zero managed bytes in all nine post-change allocation probes per fixture. Retained scratch is globally capped at 128 KiB payload, rather than multiplied by batch count. The first use/growth allocates that cache; larger meshes still allocate a temporary array. Unity's estimated Mesh memory was unchanged for every fixture. No process peak RAM, GPU residency, or device thermal measurements were taken.

The old nonzero-offset fixture produced 1,024 incorrect IDs. The updated implementation produced zero incorrect IDs for all fixtures. Shared vertices retain the previous last-incident-triangle convention, while unused vertices are cleared on buffer reuse. The GeometryPool EditMode suite passed all 16 tests, including five new cases covering ranges, reuse, empty geometry, and oversized UInt32 meshes.

Interpretation and remaining limits:

1. Large real sketches confirm benefits for partial selection, especially Galactic Cat. The effect depends on how many cold source batches are touched, not just total stroke count. The complete per-size data above takes precedence over the earlier small-fixture headline.
2. Select-all does not show a reliable speedup; some candidate medians are slower and retained cache capacity can be higher. Large selection/release operations still take hundreds of milliseconds. No steady rendering FPS improvement is established by this change.
3. Batch.RemoveSubset shrinks geometry when removing the trailing subset. GeometryPool.NumVerts currently forces a full cache restore even when that shrink empties the batch. This explains why large/all selections can lose the cold-copy benefit and identifies a concrete next optimization. This follow-up benchmark does not implement that optimization.
4. CPU scopes are nested: do not add GeometryPool.FullReload/Batch.Append to direct command CPU. Mesh uploads are recorded separately. Frame timings include Editor overhead and waits; the 60 FPS cap prevents inferring unrestricted throughput. GPU timings apply only to settled continuous phases, not discrete command attribution. Per-call allocation is unavailable on this Mono runtime; frame GC includes harness/Editor activity. Native peak is sampled Unity tracked allocations, not process peak RAM. Mobile results remain unmeasured.
5. Existing legacy metadata-upgrade assertions occur during load setup. No new geometry or batch assertion was observed in these sweeps. Earlier geometry parity tests cover the implemented cold-copy path; these runs additionally validate matching geometry counts, not a new pixel-level visual comparison.

**Phase 11: avoid restoring cold vertices just to shorten a batch.**

Implementation commit: `b2ecc2934`.

26 October 2026. This comparison isolates the new fix against `c6e263e24`, which already includes the earlier branch optimizations. It is not a whole-branch comparison against the original app.

A cold batch now tracks its live vertex count separately from its physical mesh buffer. Removing a tail uploads the shorter index list without restoring or uploading vertex channels. Later copies and edits respect the live count; hidden indices stay hidden. Empty batches still reset immediately. If the unused buffer tail would exceed the live prefix, the existing full compaction path runs instead. This bounds the newly retained tail without adding another vertex cache.

Two rounds per version, each with an unmeasured warmup and three fresh-load trials per selection size, give six measurements per operation and 192 measured phases. Each trial contains stationary rendering, selection, dragging, and releasing the moved selection. Loading is outside the measured phases. Batch mode and cache eviction are enabled. Environment: Unity 6000.6.0f1 Editor, Ryzen 7 7800X3D, RTX 4090, D3D12, 1280 x 720, monoscopic, fixed camera, 60 fps target and vsync off. Home Office intentionally omits its unavailable reference image.

The clearest gains are lower upload work and retained vertex-cache capacity. Montana selection's pooled median falls 8.6%, while upload CPU falls 35.9% and vertex arrays fall by 45.89 MiB (39.5%). The physical vertex-buffer payload grows by 2.11 MiB. Its longest-frame median falls from 328.70 to 290.78 ms.
